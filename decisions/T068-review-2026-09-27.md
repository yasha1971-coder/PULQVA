## Applied finding: align query and accepted results

The baseline asks for any video among ten results, then retains only WebM <=8 MiB.
This can produce too few choices even when supported files exist further down the
search results. The official CirrusSearch reference defines exact quoted filemime
and filesize in kilobytes of 1024 bytes. Add filemime:"video/webm" and filesize:<8192
while retaining filetype:video, File namespace and every local MIME/size/URL check.
Use iilimit=1 explicitly to match the parser's one-revision contract. This is a
query-efficiency hypothesis justified by the APIs, not a measured live improvement.
Do not present advisory server filters as a security boundary.

## Transport and comparative decision

Keep the official Commons API for this first provider rather than adding public
SearXNG-instance dependence. SearXNG's official Search API documents that formats
must be enabled per instance; JSON can be forbidden. It is a later provider option,
not an account-free availability guarantee or a requirement for this vertical slice.

The executor needs maintained HTTP/TLS support. Current reqwest documentation
exposes explicit proxy, redirect, retry, decompression and timeout controls; defaults
are not PULQVA's policy (redirects are followed and protocol NACK retries can occur).
Candidate for B: endpoint-private reqwest with Rustls, narrowly enabled features,
no caller URL/client overrides, system proxy disabled BEFORE adding the verified
socks5h proxy, no redirect/referer/cookies/implicit retries, bounded streaming body.
This is a candidate design, NOT a new dependency adoption or a tested executor.
Inspect the exact release source/features/MSRV and generate its real Cargo.lock
before implementation is accepted. Do not invent checksums or reuse latest docs
as evidence for an older release. No host-installed curl or custom TLS stack.

## Mandatory B/C evidence, not optional hardening detours

B must test observed SOCKS remote hostname forwarding, TLS hostname/certificate
rejection, refused/terminated proxy, ambient proxy/NO_PROXY poisoning, redirects,
non-success HTTP, oversized/chunked/truncated bodies and total deadline. A ready
token does not prove that the Tor child is still running. No direct retry route.
Tests must distinguish a local controlled transport fixture from actual live Tor.

C must obtain choices at run time from the API for the input text and validate
selection against that exact presented response. Require real retrieval via the
existing media adapter, bounded owned output, process termination before cleanup,
and a receipt binding page/locator/selection to actual bytes, size and digest.
Do not rely on FileReceipt::new or HTTP 200 alone as proof. Server SHA-1 is declared
metadata; compare actual content and record independent local SHA-256, without
claiming authenticity from SHA-1. Keep the source description link for attribution;
retrieval is not permission to redistribute under unspecified licensing.

The existing live example's size check/retry loop is evidence to reuse, not proof
that output quotas, atomic publication and failure cleanup are already implemented
in the production executor. Inspect these gaps when wiring C, not after announcing E2E.
T066 sealed-stage/Unix-link cleanup and other inherited race/retention limitations
remain release blockers where applicable; green happy-path tests do not erase them.

A passing Windows bootstrap timeout counts only as negative fail-closed evidence.
Positive Windows and Linux request-to-file runs remain mandatory. No arbitrary
language/AI understanding, general Internet coverage, UI/ZIP readiness or progress
percentage is inferred from local tests. Following this correction, proceed directly
to B rather than expanding A with optional features.
